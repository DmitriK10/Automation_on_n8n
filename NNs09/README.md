# Урок 9 — Заявка → ИИ → таблица → оплата

Домашнее задание, вариант 1 (базовый — повтор за экспертом).

Сценарий принимает заявку с формы, разбирает её моделью GigaChat, пишет строку в
таблицу NocoDB, собирает ссылку на оплату ЮMoney и отправляет клиенту письмо со
счётом.

## Что в папке

| Файл | Что это |
|---|---|
| `NNs09.docx` | отчёт по заданию со скриншотами |
| `workflow-hw09.json` | сценарий n8n в выгрузке |
| `shots/` | скриншоты для отчёта |
| `letter_body.txt` | текст письма, прочитанный из ящика по IMAP |

В выгрузке сценарий неактивен (`active: false`) — это нормально: активность
задаётся публикацией, шаг 2 ниже.

Скрипты проверки и сборки (`audit_workflow.py`, `audit_report.py`, `build_docx.py`,
`capture_final10.mjs`, `check_inbox.py`) остались в рабочей папке — в сдачу они не
входят.

## Как развернуть

1. Импортировать `workflow-hw09.json` в n8n 2.x:

   ```
   docker cp workflow-hw09.json n8n-lab:/tmp/wf.json
   docker exec n8n-lab n8n import:workflow --input=/tmp/wf.json
   ```

2. Опубликовать. В n8n 2.x одного `active=1` в базе недостаточно — форма не
   зарегистрируется, пока сценарий не опубликован:

   ```
   docker exec n8n-lab n8n publish:workflow --id=Hw09ZayavkaPay01
   docker restart n8n-lab
   ```

   В журнале должно появиться `Activated workflow "…"`.

3. Подождать 10–15 секунд после перезапуска. `/healthz` отвечает 200 раньше,
   чем сценарии активируются, поэтому проверять надо саму форму:

   ```
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5678/form/zayavka-oplata
   ```

   200 — форма открывается. 404 — сценарий ещё не активен.

4. Заменить учётные данные в трёх местах на свои:

   | Нода | Что нужно |
   |---|---|
   | `3. Токен GigaChat`, `4. GigaChat — разбор заявки`, `11. Письмо от ИИ` | ключ авторизации GigaChat (Basic, base64 от `client_id:client_secret`) |
   | `6. Запись в CRM`, `13. Статус в CRM` | токен NocoDB (`xc-token`) |
   | `12. Письмо клиенту` | SMTP-доступ Яндекс.Почты (пароль приложения, не основной пароль) |

   В нодах записи и обновления статуса адрес задан как
   `http://nocodb:8080/api/v2/tables/mqpogc3flc6trmz/records` — это имя
   контейнера NocoDB в docker-сети. При другом окружении заменить на свой адрес,
   а `mqpogc3flc6trmz` — на id своей таблицы.

5. В ноде `7. Параметры платежа` заменить номер кошелька `4100118895710219`
   на свой. Номер должен начинаться с `4100` и содержать 14 цифр.

6. В таблице NocoDB завести варианты статуса ровно в таком написании:
   `Ожидает оплату`, `Оплачено`, `Отклонено`, `Новая заявка`,
   `Ссылка отправлена`. NocoDB сравнивает значения строго: «ожидает оплату»
   строчными буквами будет отвергнуто с ошибкой
   `Invalid option(s) provided for column Статус`.

## Что проверить после развёртывания

- форма открывается и принимает шесть полей;
- в панели OUTPUT ноды 4 приходит JSON с шестью полями;
- в таблице появляется строка со статусом «Ожидает оплату»;
- ссылка QuickPay отвечает 302 на GET без перехода по редиректу (форма оплаты жива);
- на почту приходит письмо со ссылкой;
- статус строки меняется на «Ссылка отправлена».

## Что важно знать про этот сценарий

**Форма принимает только `multipart/form-data`.** Поля называются
`field-0` … `field-5`, а не `name`/`contact`/… — страница формы сама так
отправляет. Если отправлять данные программно, нужно использовать `field-N`,
иначе все значения придут пустыми.

**`webhookId` должен совпадать с `path`.** Иначе n8n регистрирует форму по
`webhookId`, и адрес `/form/<path>` отдаёт 404.

**Проверка ссылки — отдельная нода.** ЮMoney отвечает на GET-запрос кодом 302,
а n8n считает любой не-2xx ответ ошибкой. Нода `10a. Разбор проверки ссылки`
трактует 302 как успех и выставляет `link_ok = true`.

**Платёж не проводится.** Сценарий создаёт ссылку и отправляет её, но деньги не
переводит и не получает уведомление о поступлении. Статус «Оплачено» в этом
сценарии не появляется — для него нужен отдельный сценарий обработки
HTTP-уведомления ЮMoney с проверкой подписи.

**Ссылка `confirm.xml` — постоянная.** POST-запрос к ЮMoney из урока отдаёт 302
на `/transfer/quickpay?requestId=…`, а это одноразовая сессия: она живёт до
первого открытия и клиенту отдавать её нельзя.
