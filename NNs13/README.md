# Урок 13. Финал модуля. Центр автоматизации

Вариант 1 (Базовый). Отчёт о выполнении практики.

## Короткий комментарий

В Subworkflow вынесены два переиспользуемых блока: «Поиск в базе» (вопрос → эмбеддинг → Qdrant → готовый контекст) и «Отправка результата на почту» (готовый ответ → письмо). Основной сценарий остаётся дирижёром: две точки входа, развилка, вызов GigaChat и склейка результата. Уведомление об ошибке уходит письмом на owner@n8n-lab.local из Error Workflow Hw13ErrorHook001, привязанного через настройки всех трёх рабочих сценариев; в письме сценарий, нода, текст ошибки, режим запуска и ID выполнения. Работает центр ежедневно в 09:00 по Europe/Moscow: по расписанию chatInput пустой, поэтому развилка подставляет фиксированный вопрос про условия возврата товара.

## Что требовалось

Собрать «центр автоматизации»: основной сценарий вызывает Subworkflow, Subworkflow опубликован, есть Error Workflow с Error Trigger и узлом уведомления, Error Workflow привязан через настройки сценария, есть запуск по расписанию. Проверить: ручной запуск, запуск по расписанию и намеренную ошибку с уведомлением. Сдать 6 скриншотов и короткий комментарий.

## Основной сценарий: цепочка узлов

| № | Узел | Тип | Что делает |
|---|---|---|---|
| 1 | Чат | `chatTrigger` v1.4 | Точка входа 1: сообщение в чате, публичный вебхук `center-hw13-chat` |
| 2 | Расписание | `scheduleTrigger` v1.3 | Точка входа 2: ежедневно в 09:00 |
| 3 | Единая точка входа | `code` v2 | Развилка: если есть `chatInput` — берём его, иначе фиксированный вопрос. Отдаёт `{query, source}` |
| 4 | Поиск в базе | `executeWorkflow` v1.3 | Вызов Subworkflow `Hw13SearchKb0001` |
| 5 | Подготовка токена | `code` v2 | Генерирует `RqUID` для запроса токена |
| 6 | Токен GigaChat | `httpRequest` v4.2 | OAuth GigaChat, `form-urlencoded`, scope `GIGACHAT_API_PERS` |
| 7 | Ответ GigaChat | `httpRequest` v4.2 | Запрос к `/api/v1/chat/completions` с контекстом из Subworkflow |
| 8 | Разбор ответа | `code` v2 | Достаёт текст ответа |
| 9 | Отправка на почту | `executeWorkflow` v1.3 | Вызов Subworkflow `Hw13SendMail001` |
| 10 | Ответ в чат | `code` v2 | Возвращает `{output}` из «Разбор ответа», чтобы вывод почтового Subworkflow не попал в чат |

Развилка «Единая точка входа» нужна потому, что у сценария два триггера: чат передаёт `chatInput`, расписание — ничего. Без развилки расписание падало бы на пустом запросе.

## Subworkflow «Поиск в базе» (`Hw13SearchKb0001`)

| Узел | Тип | Что делает |
|---|---|---|
| Старт поиска | `executeWorkflowTrigger` v1.2 | Вход `passthrough` |
| Подготовка запроса | `code` v2 | Нормализует вопрос |
| Эмбеддинги вопроса | `httpRequest` v4.2 | ProxyAPI, `text-embedding-3-small`, 1536 измерений |
| Сборка запроса | `code` v2 | Собирает тело запроса к Qdrant, id точек — UUID |
| Поиск в Qdrant | `httpRequest` v4.2 | `limit 4`, `with_payload` |
| Подготовка контекста | `code` v2 | Возвращает `{query, found, hits, top_score, context}` |

Вход: `query`. Выход: `query`, `found`, `hits`, `top_score`, `context`.

## Subworkflow «Отправка результата на почту» (`Hw13SendMail001`)

| Узел | Тип | Что делает |
|---|---|---|
| Старт отправки | `executeWorkflowTrigger` v1.2 | Вход `passthrough` |
| Подготовка письма | `code` v2 | Берёт `to`, `subject`, `mail_body` (или `text`) |
| Письмо | `emailSend` v2.1 | Отправка через SMTP `mailpit-lab` |
| Итог отправки | `code` v2 | Возвращает статус отправки |

## Error Workflow (`Hw13ErrorHook001`)

| Узел | Тип | Что делает |
|---|---|---|
| Перехват ошибки | `errorTrigger` v1 | Получает объект ошибки от n8n |
| Разбор ошибки | `code` v2 | Собирает тему и текст письма: сценарий, нода, текст ошибки, режим запуска, ID выполнения |
| Письмо об ошибке | `emailSend` v2.1 | Письмо на `owner@n8n-lab.local` |

Пример реального письма:

```
Тема: Сбой автоматизации: Урок 13 — Центр автоматизации

Сценарий: Урок 13 — Центр автоматизации
Нода со сбоем: Поиск в Qdrant
Ошибка: The DNS server returned an error, perhaps the server is offline
Режим запуска: webhook
ID выполнения: 133
Время: 01.11.2026, 22:56:08

Откройте Executions в n8n и найдите выполнение 133.
```

## Что пришлось починить по дороге

1. **Тело запроса к GigaChat ломало JSON.** Контекст из Qdrant содержит переводы строк, а они недопустимы внутри строкового литерала JSON. Тело переведено на `{{ JSON.stringify(...) }}`. Ошибка воспроизводилась как `Bad control character in string literal in JSON at position 456`.

## Честные оговорки

- **Расписание проверено ускорением.** Ждать 09:00 живьём бессмысленно, поэтому интервал временно переключался на 1 минуту. Автоматические запуски получены и зафиксированы, затем расписание возвращено на «каждый день в 09:00» — на скриншоте 05 именно итоговая настройка.
- **Ошибка проверена настоящая, не имитация.** Я останавливал Qdrant, а не подменял URL: сообщение «DNS server returned an error» — подлинный ответ сети, после проверки контейнер поднят обратно.
- **Почта — локальный mailpit, не реальная доставка.** Письма проверены через API mailpit и веб-интерфейс на `127.0.0.1:8025`.
- **GigaChat embeddings недоступны** на текущем ключе (`402 Payment Required` для всех моделей эмбеддингов), поэтому в Subworkflow используются эмбеддинги ProxyAPI — как и в уроке 12.

- **Вход в интерфейс n8n.** Для съёмки скриншотов требовался вход в интерфейс n8n. Присланный пароль сервер не принял (401), поэтому пароль владельца временно заменялся служебным. После съёмки исходный хеш восстановлен из резерва, служебный пароль проверен — теперь он даёт 401. Резервные копии удалены.
