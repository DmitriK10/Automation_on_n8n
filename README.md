# Автоматизация бизнес-процессов на n8n

Учебный трек по n8n курса **«Вайб-кодинг и автономные агенты»** (Zerocoder) — 15 работ: от схемы процесса на BPMN до центра автоматизации с Subworkflow, Error Workflow и RAG-поиском по своей базе знаний.

Репозиторий собран как рабочая тетрадь: в каждой папке — отчёт с заданием и скриншотами, выгрузка сценария в `.json` и, где есть что сказать по существу, `README.md` с разбором грабель.

## Что здесь самое полезное

Три работы показывают законченные бизнес-процессы, а не отдельные ноды:

| Работа | Что делает | Для какой задачи |
|---|---|---|
| **[NNs09](NNs09/)** | Форма → GigaChat разбирает заявку → запись в NocoDB → ссылка на оплату ЮMoney → письмо клиенту | Приём заявок с сайта: разбор свободного текста моделью, CRM-строка и выставление счёта без человека |
| **[NNs13](NNs13/)** | Центр автоматизации: основной сценарий + 2 Subworkflow + Error Workflow + расписание + RAG по Qdrant | Основа для поддержки: переиспользуемые блоки, уведомление админу при сбое, работа по расписанию |
| **[NNs12](NNs12/)** | RAG: документ → чанки → эмбеддинги → Qdrant → ответ только по найденному | ИИ-помощник по своей документации, который говорит «нет информации», а не выдумывает |

## Что выяснилось на практике

Это не пересказ уроков, а расхождения между текстом задания и поведением системы, которые пришлось разбирать:

| Наблюдение | Как правильно |
|---|---|
| В уроке 12 указана размерность вектора 2056 — такой нет ни у одной модели эмбеддингов GigaChat | Коллекция создана под реальную размерность 1536 |
| Ключ GigaChat для эмбеддингов возвращает `402 Payment Required` — эмбеддинги тарифицируются отдельно | Векторы считает OpenAI-совместимый шлюз, генерация осталась на GigaChat |
| В n8n 2.x `active: true` в базе не регистрирует вебхук | Нужна публикация: `n8n publish:workflow` / `POST /rest/workflows/{id}/activate` |
| OAuth Сбера отвечает `415 Unsupported Media Type` на JSON | Только `application/x-www-form-urlencoded` |
| У Сбера сертификат Минцифры, которого n8n не знает | `Ignore SSL Issues` в HTTP-нодах к GigaChat |
| `cp database.sqlite` даёт неполный бэкап — база в режиме WAL | `sqlite3 ".backup"`, а копию проверять в `?immutable=1` |
| Без `config` и `N8N_ENCRYPTION_KEY` база открывается, а подключения — нет | Ключ шифрования обязан быть в комплекте бэкапа |
| Форма n8n принимает только `multipart/form-data`, поля называются `field-0`…`field-5` | При программной отправке использовать `field-N`, иначе значения придут пустыми |
| `webhookId` должен совпадать с `path` | Иначе `/form/<path>` отдаёт 404 |
| Порог по score в RAG не работает: вопрос вне документа дал близость 0.5153, а законный — 0.5089 | Отбирать по смыслу должна модель, а не порог |

## Как запустить любую работу

1. Поднять n8n (см. `NNs02`):

   ```bash
   docker run -d --name n8n-lab -p 127.0.0.1:5678:5678 \
     -v n8n-lab-n8n-data:/home/node/.n8n \
     -e GENERIC_TIMEZONE=Europe/Moscow -e TZ=Europe/Moscow \
     n8nio/n8n:2.27.5
   ```

2. Импортировать `workflow-*.json` из нужной папки:

   ```bash
   docker cp workflow.json n8n-lab:/tmp/wf.json
   docker exec n8n-lab n8n import:workflow --input=/tmp/wf.json
   ```

3. Создать подключения (credentials) под свои ключи — в выгрузках сценариев ключей нет, они хранятся в подключениях n8n.

4. Опубликовать сценарий, если он работает через вебхук или форму, и открыть его адрес.

Детали по конкретной работе — в её `README.md` (NNs09–NNs13) или в отчёте `.docx`.

## Чего в репозитории нет

Ключей, паролей, токенов и файлов `.env` — по требованиям заданий они не прикладываются. В отчётах они также вырезаны.
