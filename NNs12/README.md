# NNs12 — ИИ-помощник со своей базой знаний (упрощённый RAG)

Домашнее задание, вариант 1 (базовый). Собрана полная RAG-цепочка в n8n:
документ → фрагменты → эмбеддинги → Qdrant → поиск по смыслу → ответ
только по найденному тексту.

## Три отступления от текста урока

### 1. Размерность вектора — 1536, а не 2056

В уроке указано «размер вектора 2056». Такой размерности нет ни у одной
модели эмбеддингов GigaChat:

| Модель | Размерность |
|---|---|
| Embeddings | 1024 |
| Embeddings-2 | 1024 |
| EmbeddingsGigaR | 2560 |
| GigaEmbeddings-3B-2025-09 | 1024 |

Похоже, в тексте урока переставлены цифры у 2560. Коллекция под 2056 не
приняла бы ни один вектор: Qdrant сверяет длину вектора с конфигурацией.
Коллекция создана под реальную размерность выбранной модели — 1536.

### 2. Эмбеддинги не на GigaChat

Ключ GigaChat, использованный в уроках 7 и 8, для эмбеддингов не работает:
чат отвечает, а все четыре модели-эмбеддера возвращают `402 Payment Required`.
Доступ к эмбеддингам в GigaChat тарифицируется отдельно. Проверено
перебором всех доступных моделей — ответ одинаковый.

Эмбеддинги построены на `text-embedding-3-small` (1536 измерений) через
OpenAI-совместимый шлюз. Генерация ответа осталась на GigaChat, как в уроке.
Логика RAG не изменилась: две модели с разными ролями, одна модель считает
векторы и документа, и вопроса.

### 3. В ветке загрузки нет ноды токена

Схема урока начинается с получения токена GigaChat, и в ветке загрузки эта
нода тоже есть. Здесь её нет — это прямое следствие второго отступления.
Токен GigaChat нужен только для обращений к самому GigaChat; векторы
документа считает шлюз, который принимает постоянный ключ в заголовке.
Ноде токена в ветке загрузки нечего было бы делать — она отработала бы
вхолостую. В ветке ответов токен остался: там он нужен для финального
обращения к модели.

## Развёртывание Qdrant

```bash
docker run -d --name qdrant-lab \
    --network n8n-lab --restart unless-stopped \
    -p 127.0.0.1:6333:6333 -p 127.0.0.1:6334:6334 \
    -v qdrant-lab-storage:/qdrant/storage \
    qdrant/qdrant:latest
```

Контейнер в одной сети с n8n, поэтому из сценария обращение идёт по имени
`http://qdrant-lab:6333` — порты наружу не нужны.

Создание коллекции:

```bash
curl -X PUT http://127.0.0.1:6333/collections/n8n-lab-kb \
  -H 'Content-Type: application/json' \
  -d '{"vectors": {"size": 1536, "distance": "Cosine"}}'
```

## Как устроены ветки

### Ветка загрузки

```
Ручной запуск
  → Документ базы знаний      текст FAQ
  → Нарезка на чанки          8 фрагментов, перекрытие 80
  → Собрать пачку             все фрагменты одним запросом
  → Эмбеддинги фрагментов     POST /embeddings
  → Собрать точки             вектор + текст + номер
  → Qdrant: загрузить точки   PUT /collections/{name}/points
  → Итог загрузки
```

Нарезка идёт **по абзацам**, а не по символам: абзацы склеиваются, пока
длина не подойдёт к 500 символам. Принудительная резка включается, только
если отдельный абзац сам длиннее лимита. Так фрагмент совпадает со смысловым
разделом и не рвётся пополам.

### Ветка ответов

```
Чат                          Chat Trigger
  → Подготовка запроса       RqUID + вопрос
  → Токен GigaChat           POST /oauth, form-urlencoded
  → Эмбеддинги вопроса       та же модель, что для документа
  → Сборка запроса           вектор + limit 4 + with_payload
  → Поиск в Qdrant           POST /points/search
  → Подготовка контекста     текст фрагментов
  → Ответ GigaChat           system prompt + контекст
  → Ответ в чат
```

Одно отличие от схемы урока: нода токена стоит не первой, а после подготовки
запроса. Функционально это безразлично — токен требуется только на шаге
«Ответ GigaChat», а подготовка запроса от него не зависит, — но раз порядок
в уроке другой, называю это прямо.

Системный промпт, который держит помощника в рамках документа:

```
Ты — помощник интернет-магазина КофеТочка.
Отвечай ТОЛЬКО по фрагментам базы знаний, которые даны ниже.
Если ответа в них нет — так и скажи:
  "В базе знаний нет информации по данному запросу".
Ничего не придумывай. Отвечай коротко: 1-3 предложения, по-русски.
```

## Грабли, которых нет в тексте урока

| Что видно на практике | Как правильно |
|---|---|
| Qdrant всегда возвращает N ближайших точек, «ничего не найдено» не бывает | отбирать по смыслу должна модель, а не порог по score |
| Вопрос вне документа дал близость 0.5153 — выше, чем законный вопрос про выезд мастера (0.5089) | порог по score не работает: он срежет и правильные ответы |
| В n8n 2.x флаг `active: true` не регистрирует вебхук | нужен `POST /rest/workflows/{id}/activate` с `versionId` в теле |
| OAuth Сбера на JSON отвечает `415 Unsupported Media Type` | только `application/x-www-form-urlencoded` |
| Вебхук чата отвечает 404 при `healthz 200` | проверять готовность по конкретному адресу |
| У Сбера сертификат Минцифры, которого n8n не знает | `Ignore SSL Issues` в HTTP-нодах к GigaChat |

## Как воспроизвести

1. Поднять Qdrant (команда выше) и создать коллекцию.
2. Импортировать `workflow-01-load.json`, создать два подключения:
   - `httpHeaderAuth` для GigaChat: заголовок `Authorization`, значение
     `Basic <ключ авторизации>`;
   - `httpHeaderAuth` для эмбеддингов: заголовок `Authorization`, значение
     `Bearer <ключ шлюза>`.
3. Запустить ветку загрузки — в коллекции появится 8 точек.
4. Импортировать `workflow-02-query.json`, подставить те же подключения.
5. Включить сценарий и открыть чат: `/webhook/rag-chat-hw12/chat`.

Ключи в файлах сценариев не хранятся — они лежат в подключениях n8n.
